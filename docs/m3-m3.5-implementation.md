# M3 / M3.5 实现记录

更新时间：2026-09-01

## 当前结论

M3 和 M3.5 已接入 `AgentSession -> runStep -> Executor -> ToolRouter -> ToolRuntime` 主链。旧 `Tool` 接口仍可注册，但注册时会拆成不包含执行函数的 `ToolSpec` 与内部 `ToolRuntime`；模型只收到 direct exposure 的 spec。

## M3

- `ToolSpec` 描述名称、namespace、schema、exposure 和并发元数据。
- `ToolRuntime` 只负责运行，`ToolRegistration` 保存 spec/runtime/source/version。
- `ToolRegistry.registerDefinition()` 检查 schema、名称和冲突；legacy `register()` 保持兼容。
- `ToolRouter` 统一处理可见性、schema 字段路径校验、M1 preflight、preview、permission、approval、revalidation、sandbox admission、runtime 和结果标准化。
- `StreamingToolExecutor` 使用 promise 唤醒的 read/write gate：只读调用可共享，写调用独占，结果按提交顺序返回。
- timeout 创建 linked `AbortController`，取消和超时会传递给 runtime。

## M3.5

- `shell-tokenizer.ts` 支持 bash/cmd/PowerShell 可替换 dialect、引号、转义、控制操作符、重定向、命令替换、变量和 glob 标记。
- `shell-ast.ts` 构建 command chain、nested group、argv 和 redirect 节点。
- `DefaultCommandAnalyzer` 分析每个子命令，并按 `deny > ask > allow` 合并；预览包含节点风险、关系和受影响 canonical paths。
- `SandboxProvider` 表达 filesystem、network、subprocess、cwd、environment、timeout、cancellation 和实际 enforcement 能力。
- `SandboxManager` 已接入 `ToolRouter`，`run_command` 会携带规范化 `SandboxProfile`，strict provider 必须满足 OS、文件系统、网络和进程树保证。
- `LocalSandboxProvider` 使用受限环境和 cwd 的单次子进程 adapter；它明确 `enforcement: "best_effort"`，不伪装成完整 OS 沙箱。动态命令在未提供 OS 边界时拒绝，network 能力不足时拒绝。
- Windows 默认使用 `WindowsDockerSandboxProvider`：固定 workspace bind mount、`network=none`、只读 rootfs、capability drop、禁止提权、最小环境和容器清理。`SWE_SANDBOX_MODE=best-effort` 才启用本地 adapter。

## 测试

新增覆盖：

- 引号、转义、嵌套命令和未闭合语法。
- 多命令链的子命令风险合并、重定向和动态展开。
- Registry spec/runtime 分离、注册冲突和 schema 字段路径错误。
- 缺失 sandbox capability 时 runtime 不启动。
- strict profile 缺少实际强制能力时 admission 不启动 runtime。
- 任意环境 patch 中的 secret key 不会传入本地子进程。
- 只读并发、写独占以及提交顺序结果。

验证命令：`npm run typecheck`、`npm test`、`npm run build`。

## 未完成边界

- Windows native ACL/restricted-token/WFP backend、Windows Job Object 独立资源 provider、Linux Landlock/bubblewrap、macOS Seatbelt 和 provider-owned persistent session 尚未实现。
- 当前 Windows strict 是 Docker Desktop 容器级边界；Docker Desktop 不可用时不会静默回退到普通 Shell。
- 真实 Docker Desktop 文件/网络边界测试需要在安装 Docker 的 Windows 环境执行；当前测试只验证协议、能力准入和本地 adapter 行为。
- Session/Turn 状态机已在 M4 实现；Transcript/Resume/Fork 和多 Agent 仍属于 M5+。
